# Интенсивное наблюдение

Система поддержки клинических решений для мониторинга тяжёлых пациентов: отслеживание динамики показателей, немедленная реакция на отклонения, автоматический расчёт клинических шкал и интерпретация типичных клинических паттернов.

> **Это не медицинское изделие.** Приложение помогает разобраться во внесённых данных; диагноз и лечение определяет врач. Перед работой с реальными данными пациентов нужны правовая основа обработки персональных данных, согласование с руководством и службой информационной безопасности (см. раздел 13 в [PRD.md](PRD.md)).

## Возможности

- **Ввод данных** медсестрой или медбратом с подсветкой отклонений в реальном времени и предварительной оценкой: какие сигналы добавит запись ещё до сохранения.
- **Автоматические шкалы:** NEWS2 (шкалы SpO₂ 1 и 2), qSOFA, SOFA с ΔSOFA, APACHE II с ориентировочной летальностью, СКФ по CKD-EPI 2021.
- **Шкалы, вносимые персоналом:** RASS, CAM-ICU, Брейден, NUTRIC, NRS-2002, MUST, CPOT, BPS, 4T, ISTH, SIC, Caprini, Padua, IMPROVE, IMPROVE-VTE, HAS-BLED — с автоотметкой пунктов по диагнозу, анализам и данным мониторинга.
- **Правила интерпретации:** картина шока, критерии септического шока, КЩС с компенсацией по Винтеру и анионным интервалом, ОПП по KDIGO, олигурия, водный баланс с оценкой неощутимых потерь, механика дыхания (движущее давление, статический комплаенс, резистивное давление, механическая мощность), падение гемоглобина и тромбоцитов, коагулопатия потребления и другие.
- **Уведомления о критических сигналах** у любого пациента отделения: звук, панель и системное уведомление, независимо от открытой карточки.
- **Обзор отделения** по тяжести и отчёт при передаче смены в структуре SBAR.
- **Архивирование выписанных** с обязательной выгрузкой CSV и JSON — освобождает место в базе.
- **Прослеживаемость:** у каждой записи есть время измерения, время создания, автор и роль. Записи не удаляются — ошибочные аннулируются с указанием причины.
- **Разбор для врача** с помощью ИИ по запросу, с сохранением в карточке пациента.

## Как запустить

Приложение работает в трёх режимах, и у каждого свои возможности.

| | Artifact в Claude | Собственный адрес (PWA) | Файл на диске |
|---|---|---|---|
| Общая база отделения | есть | нет | нет |
| ИИ-разбор и выгрузка файлов | есть | нет | нет |
| Установка на устройство, работа без сети | нет | есть | нет |

**1. Как Artifact в Claude — рабочий режим.** Доступны общая база отделения в реальном времени, ИИ-разбор и сохранение файлов. Опубликованная версия живёт по одному адресу и обновляется на месте, чтобы не появлялись дубли.

**2. С собственного адреса — режим PWA.** Страница устанавливается на телефон, планшет или компьютер и открывается без сети. Когда браузер готов к установке, в шапке появляется кнопка «Установить»; в Safari на iPhone и iPad она показывает порядок действий вручную («Поделиться» → «На экран „Домой“»). У установленного приложения есть ярлыки «Добавить пациента» и «Нормы и пороги». Service worker кэширует только саму страницу и её ресурсы; данные пациентов в кэш не попадают и хранятся в браузере устройства. Новая версия применяется не сама, а по кнопке «Обновить» в баннере, чтобы не прерывать заполнение формы. Годится для демонстрации и работы в одиночку, но не для отделения: общей базы нет.

Для установки нужен HTTPS (`localhost` тоже подходит). Проверить режим локально: любой статический сервер в корне репозитория, например `python3 -m http.server`, и открыть `http://localhost:8000/`.

Рабочий адрес — GitHub Pages: **https://laubayevilfat.github.io/icu-monitoring/**. Публикацию выполняет [`.github/workflows/pages.yml`](.github/workflows/pages.yml) при каждом изменении ветки `main` (и по кнопке «Run workflow»): репозиторий отдаётся как есть, сборки нет. Перед первым запуском в настройках репозитория нужно один раз включить Pages: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

**3. Локально — для разработки.** Откройте `index.html` в браузере: приложение перейдёт в режим без общей базы и будет хранить данные в `localStorage`, о чём выводит баннер. Service worker по протоколу `file://` не работает, поэтому установка и офлайн недоступны — для их проверки нужен любой локальный HTTP-сервер.

Сборка и зависимости не нужны ни в одном режиме.

## Разработка

`PRD.md` — источник истины и ведётся синхронно с кодом: при изменении приложения обновляются соответствующие функциональные требования, раздел 11 (проверка), 12 (известные ограничения) и 14 (дорожная карта).

Документ сводит две линии разработки. Требования с меткой ✅ описывают код в этом репозитории; требования с меткой 🔶 (дневник врача с ИИ-извлечением, препараты и дозы по функции почек, описания исследований, импорт PDF, хронология, дашборд госпитализации, дизайн-система «Прикроватный монитор») реализованы в отдельной сборке-артефакте, и их кода здесь нет. Что и как переносить между линиями — раздел 14.1 PRD.

Вычисления вынесены в чистые функции (`evaluate`, `news2`, `sofaAt`, `sofaDelta`, `apache2`, `akiStage`, `camEval`, `nutricEval`, `egfr`, `vteAdvice`) — их можно проверять независимо от интерфейса.

## Ограничения

Нормы и критические пороги ориентировочные, заданы для взрослых и редактируются в интерфейсе; до клинического использования их должны утвердить заведующий отделением и лаборатория. Полный список известных ограничений — раздел 12 в [PRD.md](PRD.md).
